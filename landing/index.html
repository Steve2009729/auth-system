What's included

Nothing you don't.

Built on FastAPI with async PostgreSQL and Redis. Every feature is production-grade and independently testable.

JWT + Refresh Rotation

Short-lived access tokens paired with rotating refresh tokens. Replay-attack detection revokes all sessions on reuse.

RBAC — Roles & Permissions

Fine-grained role-based access control. Assign roles to users, attach permissions to roles, enforce per-route.

TOTP Two-Factor Auth

Google Authenticator-compatible TOTP 2FA. QR code setup, Redis-backed session handoff, clean enable/disable flow.

OAuth2 — Google & GitHub

Drop-in Google and GitHub login. Both providers are optional — returns 501 if credentials are not configured.

Rate Limiting & Lockout

Redis sliding-window rate limits per IP per endpoint. Progressive account lockout after 3, 5, and 10 failed attempts.

Full Audit Log

Every auth event — login, logout, password change, role assignment — written to an append-only log with IP and metadata.

The core flow

AuthSystem handles the full lifecycle — registration, email verification, token refresh, logout, and 2FA — so you focus on your application.

  1. 1 POST /auth/register — create account
  2. 2 POST /auth/login — get access + refresh tokens
  3. 3 GET /users/me — call any protected route
  4. 4 POST /auth/refresh — rotate tokens before expiry 
# 1. Register
curl -X POST https://auth-system-9ai3.onrender.com/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email":"you@example.com","username":"alice","password":"Secret123!"}'

# 2. Login — receive access + refresh tokens
curl -X POST https://auth-system-9ai3.onrender.com/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"you@example.com","password":"Secret123!"}'

# 3. Call a protected endpoint
curl https://auth-system-9ai3.onrender.com/users/me \
  -H "Authorization: Bearer ACCESS_TOKEN"

# 4. Refresh — rotate tokens before expiry
curl -X POST https://auth-system-9ai3.onrender.com/auth/refresh \
  -H "Content-Type: application/json" \
  -d '{"refresh_token":"REFRESH_TOKEN"}'
import httpx

BASE = "https://auth-system-9ai3.onrender.com"

# 1. Register
httpx.post(f"{BASE}/auth/register", json={
    "email": "you@example.com",
    "username": "alice",
    "password": "Secret123!",
})

# 2. Login
res    = httpx.post(f"{BASE}/auth/login", json={
    "email": "you@example.com",
    "password": "Secret123!",
})
access = res.json()["access_token"]

# 3. Call a protected endpoint
me = httpx.get(f"{BASE}/users/me",
    headers={"Authorization": f"Bearer {access}"})
print(me.json())
const BASE = "https://auth-system-9ai3.onrender.com";

// 1. Register
await fetch(`${BASE}/auth/register`, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    email: "you@example.com", username: "alice", password: "Secret123!",
  }),
});

// 2. Login
const { access_token } = await
  fetch(`${BASE}/auth/login`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ email: "you@example.com", password: "Secret123!" }),
  }).then(r => r.json());

// 3. Call a protected endpoint
const me = await fetch(`${BASE}/users/me`, {
  headers: { "Authorization": `Bearer ${access_token}` },
}).then(r => r.json());
console.log(me);

Architecture

Clean layers. No magic.

Routers handle HTTP. Services own business logic. Models map to Postgres. Redis handles rate limits, token blacklisting, and 2FA sessions.

app/routers/

Routers

Thin HTTP layer. Request validation, auth dependencies, response serialisation. No business logic lives here.

app/services/

Services

All business logic: AuthService, SessionService, UserService. Independently testable with no HTTP concerns.

app/models/

Models

SQLAlchemy async ORM — User, Role, Permission, Session, Token, AuditLog. Full typed relationships.

app/core/

Core

Security primitives: JWT, bcrypt, TOTP, rate limiter, email, audit writer. Dependency-injectable and easy to swap.

CLI reference

Four commands. That's all you need.

Install once, use anywhere. Every command has --help detailed enough that you won't need the docs.

authsystem init 
authsystem init [--force]

Creates .env and auto-generates a secure SECRET_KEY. Use --force to overwrite an existing .env.

authsystem serve 
authsystem serve [--host] [--port] [--workers N]

Starts the API via uvicorn. Hot-reload on by default. Pass --no-reload --workers N for production.

authsystem create-admin 
authsystem create-admin --email admin@you.com

Creates a superuser with the admin role. Prompts for password if --password is omitted. DB must be migrated first.

authsystem migrate 
authsystem migrate [revision | --autogenerate -m "msg"]

Runs alembic upgrade head. Use --autogenerate to generate new migrations from model changes.

Why self-host

Your auth. Your data. Your rules.

Your data stays with you

User records, sessions, and audit logs live in your Postgres instance — on your infrastructure, under your backup policy, subject to your data retention rules. No third party can read, sell, or lose your users' data.

No per-user pricing surprises

Managed auth services charge per monthly active user. AuthSystem is flat: pay for your server, nothing else — whether you have 100 users or 100,000. Your costs don't scale with your growth.

Full control over the code

Need a custom permission model, a non-standard OAuth provider, or a bespoke audit event? Fork it, change it, ship it. MIT licensed Python — no SDK wrappers, no black boxes.
